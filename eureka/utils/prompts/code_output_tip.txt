The output of the reward function should consist of two items:
    (1) the total reward,
    (2) a dictionary of each individual reward component.
The code output should be formatted as a python code string: "```python ... ```".

Some helpful tips for writing the reward function code:
    (1) You must define multiple scalar variable constants at the top of your function; these will be automatically converted into trainable parameters.
    (2) Each reward component should have at least 2-3 associated scalar parameters that control its behavior:
        - A weight parameter that scales the magnitude of the component (e.g., position_weight = 2.0)
        - A temperature/scaling parameter that controls sensitivity (e.g., position_temp = 0.5)
        - Thresholds that determine success criteria (e.g., distance_threshold = 0.1)
    (3) When applying transformations to reward components (like torch.exp or sigmoid), always include a temperature parameter:
        - Example: torch.exp(-distance_temp * distance)
    (4) Make sure to define separate scalar variables rather than hardcoding numbers in your calculations
    (5) Make sure the type of each input variable is correctly specified; a float input variable should not be specified as torch.Tensor
    (6) Most importantly, the reward code's input variables must contain only attributes of the provided environment class definition (namely, variables that have prefix self.). Under no circumstance can you introduce new input variables.
    (7) Reward must be separated into partitions, to do this create binary condition checks to determine which portion of the task the policy is in, and then only activate certain regions of the reward function based on that subtask
        - Example: If the task can be split into two subtasks: reaching/grasping + manipulating, then create a binary check for whether or not the handles have been grasped. If this condition hasn't been met by the current state then the reward should focus only on reaching this state, if the condition is being met then the reward function should focus only on the manipulating subtask (completely zeroing the rewards associated with reaching/grasping)
    (8) Try to use state-distance style rewards as the primary driver for each subtask
    (9) Ensure a large constant reward is added after each subtask / checkpoint / check is being passed by the current state, this is to ensure that the policy stays in that advanced state and doesn't revert to hack the easier reward functions. Ideally this large constant reward should be the max possible reward from the prior reward partition / checkpoint
    (10) These binary conditions should be included in the reward dictionary to assist during replanning by checking whether or not certain stages are being reached during training, perhaps fixing the binary condition or modifying the reward function for that subtask.

Good example of scalar variable definitions:
```python
# Scalar weights and parameters (these will become trainable)
position_weight = 1.0  # Weight for position reward component
rotation_weight = 0.8  # Weight for rotation reward component
position_temp = 5.0    # Temperature parameter for position sensitivity
rotation_temp = 10.0   # Temperature parameter for rotation sensitivity
smoothing_factor = 0.1 # Smoothing factor for reward curves
threshold_distance = 0.05  # Success threshold for distance
```
